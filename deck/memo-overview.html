The problem

Assistants pay to relearn our code, every session

Ask an AI assistant a routine question — “who calls this method?” — and it has no map of the repository. It searches, opens files, reads them whole, and discards it all when the session ends. The next question starts over.

Too much context becomes a constraint

Whole files consumed during discovery crowd out the work the assistant was asked to do, and quality drops as the window fills.

The cost repeats

Nothing is retained between sessions. The same rediscovery is paid for again by every engineer, on every task.

Worst on our oldest code

Our largest and least-documented systems are exactly where an assistant reads the most files to make progress.

The approach

Index once. Answer from the index.

memo reads the repository once and builds a local index — a structural summary of every file plus a call graph of what invokes what. Relationship questions then become lookups, returned as precise file:line coordinates instead of file dumps.

1 · Index

One command. Parses the repo locally and stores the result alongside it.

2 · Integrate

Writes the instruction files that teach each assistant when to use it.

3 · Ask

The assistant reaches for memo on its own — no change to how engineers work.

4 · Stay current

Re-indexing is incremental: only changed files are re-read.

How it works

One pass over the repository, two artifacts

A structural summary of every file, and a graph of what calls what. Every answer memo returns is a lookup against one of those two — never a re-read of the repository.

The Cigna Group7
Architecture · indexing

Source in, structure out

One command walks the repository. Each file is routed to a parser for its language, which extracts the declarations and every call made inside them. Nothing else is retained.

1 · Walk
Every source file in the tree, minus anything excluded by .memoignore.
→
2 · Route by language
File extension selects the parser. Six of them cover the estate.
Python — ASTC#VB.NET JS / TSASPX / Razor
→
3 · Extract
Declarations with signature, line span and doc line; imports; TODO and HACK markers.
→
4 · Scan call sites
Every invocation, recorded with what it was called on and how many arguments it was given.
↓
Summary cache
One record per unique file content — purpose, symbol list, dependencies, and the token cost of the file versus its summary.
Call graph
A symbol table plus every call edge, each edge scored for how certain its target is. Persisted with a content fingerprint of the files it was built from.

Re-indexing is incremental: parse results are keyed by file content, so an unchanged file is never re-read. The fingerprint is how memo status knows whether the graph still matches the working tree.

Every graph command is this same walk, bounded differently. callers stops after one ring — 34 methods. impact keeps going to the entry points — 103 methods across four depths, reaching both controllers and the Kafka consumer. tests returns the 761 test methods that reach it; deadcode inverts the question and finds the 22 methods nothing calls at all.

Architecture · answering

The assistant asks; memo resolves

Engineer asks in the IDE
“What breaks if I change this?” — ordinary language, no new syntax to learn.
→
Assistant chooses memo
A generated rule file tells it which questions memo answers better than search. The engineer does not invoke anything.
→
memo runs locally
A short-lived process reads the index off disk. No server, no daemon, no network call.
↓
Call graph
Relationship questions — callers, callees, transitive reach, blast radius, covering tests.
Summary cache
Structural questions — where a concept lives, what a file is for, which symbol holds a value.
Source slice
When the body itself is needed, exactly the lines of the symbol asked for — not the file around it.
↓
Answer: ranked file:line coordinates, each carrying its confidence
Call edges are graded from the evidence in the source — a receiver whose declared type names the target ranks exact; agreement on file and argument count ranks strong; a name match alone ranks lower; and an edge the argument count rules out is dropped. Certain answers sort first, so the assistant reads the top of the list, not all of it.

Twenty-two commands, four jobs

Follow a relationship

callsWhat does this invoke?

mapWhere is this handled?

trace-stackA pasted exception trace, resolved to current lines.

Set up and keep current

initConfigure every assistant, then index.

cacheIndex one file.
statusIs the index still trustworthy?

The first two groups have no equivalent in the standard toolchain. The rest exist so the index stays honest — a stale answer is reported as stale, not returned as fact.

memo — code intelligence13
Differentiator 2

Nothing leaves the machine

memo contains no networking code of any kind. Analysis is local static parsing — there is no model to call, so there is no path by which source code could be transmitted.

No LLM API

Summaries and the call graph come from parsing, not inference. No prompt ever contains our source.

No credentials to govern

No API keys, tokens or service accounts to issue, rotate or audit.

No third party

No vendor agreement, data-processing addendum or external dependency in the critical path.

The index is written next to the repository and excluded from version control. It can be deleted at any time and rebuilt in seconds.

Accuracy improves with the code it reads

memo reads declared types from source, so a call through an interface resolves to the implementation that actually runs. On a 350-file production service this correctly resolved a further 12% of otherwise ambiguous call sites.
